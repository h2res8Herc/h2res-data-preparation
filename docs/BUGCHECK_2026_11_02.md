## Findings and corrections

| Finding | Correction and protection |
|---|---|
| A reference `max_cap` value of `341.663728186051` was assigned into a generated integer column | Industry parameters are assembled into complete records before DataFrame construction. This preserves fractional capacities, limits and equipment parameters while retaining observed regional capacities and fuel shares. |
| Integer RPS columns and investment-limit columns rejected fractional scenario values | Numeric scenario columns are promoted before assignment. Tests cover fractional renewable trajectories and selected annual investment overrides. |
| Regional product quantities could be read as integers | Physical product quantities and process coefficients support fractional regional allocation. National totals are conserved; production indices retain their intended interpretation. |
| Invalid JSON years could be truncated or raise an unhelpful type/overflow exception | Planning years, range endpoints, steps and renewable deadlines require positive finite integers. |
| A transport investment override could address stock counts or unrelated attributes | Transport overrides are restricted to annual limit fields. Invalid numeric limits are rejected during scaling rather than converted into missing/unrestricted values. |
| Incompatible local templates could fail after expensive sector preparation | The selected workbook, required sheets/headers, limit values, transport fuel mappings, complex-industry companion and applicable scenario settings are checked before source pipelines. |
| An export exception could leave a partially replaced bundle | Exports are built and checked in a staging directory. The previous bundle is replaced after successful completion. Existing user files are preserved; transformation/readiness failures write `model_export_failure.json` beside the bundle. Publication failures attempt rollback. If a Windows lock also blocks rollback, the previous data remain in an explicitly reported backup folder outside temporary cleanup. |
| Raw GENCO caches were cleaned before a new build succeeded, including unrelated countries | Raw builds run in a temporary directory first. Successful selected-country refreshes replace that selection's files and preserve other country caches. Failures retain previous cached files. |
| Countries absent from the raw plant sources could be silently skipped | The builder reports an explicit coverage error before writing GENCO files. The inspected cached sources contain no Malta plant records; no plants were fabricated to satisfy that selection. |

The installed pandas release was **3.0.2**. The stricter assignment behavior is documented in the [official pandas 3.0 release notes](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html). The corrections handle the numeric types explicitly.

## Repeating the checks

From the preparation repository:

```powershell
python -B validation/run_preparation_bugcheck.py --raw-power --with-tests
```

This writes reports and test artifacts under `validation/preparation_bugcheck` and uses the available cached country variants. The original source caches and portable reference are read for the audit.

To repeat only the repaired Croatia export:

```powershell
python generate_all_sector_inputs.py --countries HR --sectors industry --spatial-level country --out-root outputs_industry_HR --data-root data_industry_HR --industry-mode categories --no-efuels --export-only --require-model-ready
```

The open preparation window can start another run: each run launches a new generator process and loads the corrected generator code. Disable **Refresh sources** to reuse downloads when repeating source preparation.
